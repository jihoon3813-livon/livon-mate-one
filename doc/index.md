## 문서 목록

### [00. 문서 갱신 프롬프트 모음](./00_update_prompts.md)
코드 변경 후 01~07번 문서를 다시 최신화하기 위한 재사용 프롬프트. 변경 범위 파악 → 영향받는 문서 판단 → 문서별 갱신 프롬프트(7종) → 일괄 갱신 프롬프트 순서로 구성.

### [01. Architecture Discovery](./01_Architecture_Discovery.md)
시스템 전체 지도. 프로젝트 개요, 기술 스택, 디렉터리 구조, 애플리케이션 진입점(서버 4종), 핵심 컴포넌트, 시스템 데이터 흐름, 외부 시스템, 환경변수, 배포 구조. Mermaid 다이어그램 4종(전체 아키텍처 / 인증흐름 / 정산로직 / 데이터동기화) 포함.

- 핵심 발견: 서버 구현 3종 병존(`server.js`/`start_server.ps1`/Vercel), 4개 데이터 저장소 병존, Convex 공식 SDK 미사용

### [02. Use Case Trace](./02_use_case.md)
핵심 사용자 시나리오 10개를 `User → API → Handler → Service → DB → 외부시스템 → Response` 전 구간 `파일:라인` 단위로 역추적. 각 시나리오마다 10단계 분해 + 핵심 비즈니스 규칙 별도 추출.

- 다루는 시나리오: 로그인, 신규접수(+현대해상 팩스), 정산스케줄계산, 보험청구팩스발송, CTI클릭투콜, 콜로그동기화, 삼성화재드라이브동기화, CarePort간병일지, 고객만족도설문, 전산데이터초기화

### [03. 데이터 저장 구조 (DB)](./03_db.md)
DB 종류·연결설정·ORM여부·전 테이블 목록/역할/컬럼/PK·FK/인덱스/관계·트랜잭션 경계·동시성·Lock·Migration·초기화·SoftDelete·Audit·N+1·위험쿼리·성능 19개 항목 + 데이터 삭제 시 영향 분석.

- 핵심 발견: 정식 DB 아님(Convex+로컬JSON+localStorage+IndexedDB 4중 구조), 진짜 FK는 3개뿐, 인덱스 정의돼도 대부분 미사용(N+1), 관리자 삭제해도 세션 안 끊김

### [04. 위험요소 분석 (Risk Analysis)](./04_risk_analysis.md)
Critical/High/Medium/Low 4단계, 총 29개 항목. 각 항목 8필드 고정 형식(위험도/문제/발생조건/영향/관련코드/이유/근거/개선방향).

- Critical 8개(발췌): `?env=dev` 인증완전우회, 관리자 마스터비밀번호 백도어, 인증없는 전체데이터삭제, 관리자삭제 후 세션잔존, 외부서비스 자격증명 하드코딩, 주민등록번호 평문저장, 로그에 비밀번호 평문기록, CORS 전면허용+인증부재

### [05. 운영 정보 (Operation Analysis)](./05_operation_analysis.md)
실행/빌드/환경변수/외부서비스설정/DB설정/배포/배포주의사항/Migration/초기화/로그위치/장애확인/모니터링지표/Scheduler·Batch/Queue·Worker/파일저장위치/외부API장애영향/DB장애영향/재시작문제/Rollback/절대변경금지설정 20개 항목.

- 핵심 발견: `start_server.ps1`은 `server.js` 대체품 아님(팩스 발송이 항상 가짜 성공), 개인정보 담긴 업무데이터가 git에 커밋됨(반대로 자격증명 파일은 gitignore), 헬스체크·스케줄러·큐 전무

### [06. 개발자 인수인계 문서 (Handover)](./06_handover.md)
01~05번 종합 요약. 고정 20장 목차(시스템개요~인수후우선확인사항). **가장 먼저 읽을 문서.** 20장에 즉시(1주)/단기(1개월)/중기 우선순위 체크리스트 포함.

### [07. 자체 검증 (Self Review)](./07_self_review.md)
01~06번 분석 자체에 대한 자기검증. 분석 못한 영역, 근거 약한 추론, 모순되는 결과, 실행해야만 확인되는 것, 코드만으로 알 수 없는 운영정보, 신규개발자 오해 가능 지점, 추가확인 필요 파일, 누락 의존성, 장애추적 어려운 부분, 신규담당자가 물어볼 질문 20개.

- 핵심 발견: `?env=dev` 우회가 04번 서술보다 실제로 더 심각함(Convex 서버측 `dev_session_` 토큰 무검증 수용 확인), README/경영보고서가 내세운 AWS S3·STT 음성일지 기능이 코드에 전혀 없음(어느 문서도 이 모순을 지적 안 함)

## 작성 원칙 (전 문서 공통)

- 모든 서술은 `파일:라인` 근거를 표기한다.
- 추론한 내용은 **(추론)/(추정)**, 코드로 확인 불가능한 내용은 **"확인 필요"** 로 표시한다.
- 근거 없는 일반론은 배제한다.
- 각 문서 최상단에 분석 기준 커밋 해시와 작성일을 명시한다.
